# DevTeamFlow 概要设计文档

## 1. 引言

### 1.1 项目概述
DevTeamFlow 是一个基于 Scrum 原则的代码项目管理插件，旨在优化代码项目开发流程，提供项目管理、团队协作、需求跟踪及进度可视化功能。系统通过集中的缺陷管理、需求全生命周期跟踪、跨项目资源分配等功能，解决项目健康监控不足、手动需求管理导致的版本控制问题及人力资源分配不均等问题。

### 1.2 目标
- 为项目经理提供实时项目健康监控和需求全生命周期管理。
- 为团队负责人提供高效的任务分配和代码验证工具。
- 为业务分析师提供需求管理及环境依赖处理功能。
- 为项目组合经理提供跨项目资源优化和进度可视化。
- 为开发人员提供实时协作编码和代码历史追溯功能。

### 1.3 技术栈
- **后端**：Django（Python 框架，提供 Web 服务和业务逻辑处理）
- **前端**：HTML + CSS（用于页面展示和交互，结合 Django 模板）
- **数据库**：SQLite（轻量级数据库，存储项目、需求、团队等数据）
- **缓存**：Redis（可选，用于会话管理和数据同步优化）
- **其他**：Git（用于版本控制和分支管理）、VSCode Web（支持实时协作编码）

## 2. 系统架构

### 2.1 总体架构
DevTeamFlow 采用前后端分离的 MVC 架构，基于 Django 框架构建。前端通过 HTML 和 CSS 实现用户界面，后端处理业务逻辑和数据操作，SQLite 存储持久化数据，Redis（可选）用于缓存和会话管理。系统通过 RESTful API 与前端交互，支持 Git 集成以实现版本控制。

**架构分层**：
- **表现层**：HTML + CSS，呈现仪表板、甘特图、燃尽图等可视化界面。
- **业务逻辑层**：Django 后端，处理项目管理、需求跟踪、权限控制等逻辑。
- **数据访问层**：SQLite 数据库，存储项目、需求、团队成员等数据；Redis 用于缓存和会话。
- **外部集成**：Git 集成用于分支管理和 commit 历史跟踪；VSCode Web API 用于实时协作编码。

### 2.2 模块划分
系统划分为以下核心模块：
1. **项目管理模块**：
   - 功能：项目设置、需求全生命周期管理、环境依赖检查。
   - 职责：管理项目信息、需求状态、分支操作及依赖包冲突解决。
2. **可视化模块**：
   - 功能：项目仪表板、甘特图、燃尽图。
   - 职责：展示项目进度、健康指标及时间线。
3. **团队管理模块**：
   - 功能：团队成员档案管理、基于角色的访问控制、跨项目任务分配。
   - 职责：维护团队信息、权限配置及任务分配。
4. **Git 集成模块**：
   - 功能：commit 历史展示、图形化操作、冲突处理。
   - 职责：集成 Git 系统，展示树状 commit 历史，提示冲突并支持 VSCode 打开处理。
5. **实时协作模块**：
   - 功能：支持 VSCode Web 实时协作、会话安全控制、数据同步。
   - 职责：提供协作编码环境，30 分钟无活动会话超时，确保本地与云端数据同步。

## 3. 功能设计

### 3.1 项目管理
- **项目设置**：通过 Django 模型管理项目信息，支持增删改查（CRUD）。
- **需求管理**：
  - 支持需求全生命周期状态管理（新建→进行中→已实现→已关闭）。
  - 提供 API 实现需求的 CRUD 操作，包括关联 Git 分支和文档。
  - 集成 Git 命令行工具（如 `git branch`、`git tag`）管理分支。
- **环境依赖管理**：
  - 自动检测依赖冲突，通过 Python 脚本调用 `pipdeptree` 或类似工具分析依赖。
  - 支持环境模板配置，存储于 SQLite 数据库。

### 3.2 可视化
- **仪表板**：使用 Django 模板和 CSS 实现动态仪表板，展示甘特图和燃尽图。
- **甘特图**：基于时间线展示项目任务和需求进度，使用开源库（如 Chart.js）实现。
- **燃尽图**：展示剩余工作量与时间的关系，支持实时更新。

### 3.3 团队管理
- **成员档案**：通过 Django Admin 或自定义界面实现成员信息的 CRUD 操作。
- **权限控制**：基于 Django 的用户认证和权限系统（`django.contrib.auth`）实现角色访问控制。
- **跨项目分配**：通过数据库查询优化成员分配，支持多项目任务分配。

### 3.4 Git 集成
- **Commit 历史**：通过 GitPython 库获取 commit 记录，生成树状结构展示。
- **图形化操作**：通过前端界面调用 Git 命令（如 `git merge`、`git rebase`），支持冲突提示。
- **冲突处理**：检测合并冲突后，通过 VSCode Web API 打开本地文件进行编辑。

### 3.5 实时协作
- **Pair Coding**：集成 VSCode Web，支持多人实时编码，基于 WebSocket 实现数据同步。
- **会话安全**：通过 Redis 管理会话，设置 30 分钟超时机制。
- **数据同步**：使用 Django Channels（基于 Redis）实现本地与云端数据实时同步。

## 4. 非功能性设计

### 4.1 安全性
- **数据加密**：使用 Django 的加密工具（如 `django-cryptography`）对静态数据加密。
- **会话管理**：通过 Redis 实现会话超时控制，30 分钟无活动自动登出。
- **权限控制**：基于 Django 的 RBAC（角色访问控制）实现细粒度权限管理。

### 4.2 性能
- **数据同步**：通过 Redis 缓存频繁访问的数据（如会话、仪表板数据），减少 SQLite 查询压力。
- **响应时间**：优化 Django 查询，使用索引提高 SQLite 性能。

### 4.3 兼容性
- **浏览器**：支持 Chrome、Firefox、Safari、Edge 的最新版本，使用现代 CSS（Flexbox、Grid）确保界面兼容性。
- **IDE 集成**：通过 VSCode Web API 提供实时编码支持。

## 5. 外部依赖
- **Git**：用于版本控制和分支管理。
- **VSCode Web**：支持实时协作编码。
- **身份验证**：集成外部身份提供者（如 OAuth2）。
- **文档存储**：使用云端存储服务（如 AWS S3 或 Django 的文件存储系统）保存需求文档。

## 6. 系统流程

### 6.1 需求实现流程
1. 产品经理通过前端界面创建需求，存储于 SQLite。
2. 团队负责人分配任务，创建关联 Git 分支。
3. 开发人员在 VSCode Web 实现代码，提交 commit。
4. 负责人验证代码，处理冲突。
5. 产品经理验收需求，更新状态为“已关闭”。

### 6.2 冲突处理流程
1. 系统检测 Git 合并冲突，记录冲突文件。
2. 前端提示冲突，调用 VSCode Web 打开文件。
3. 开发人员手动解决冲突，提交更新。

## 7. 扩展性考虑
- **Redis 集成**：可通过配置启用 Redis，优化会话管理和数据同步。
- **模块化设计**：各模块（如需求管理、Git 集成）松耦合，支持后续添加更多扩展功能。


## 8. 风险与假设
- **风险**：
  - SQLite 在高并发场景下性能可能受限，可考虑后续迁移至 PostgreSQL。
  - Git 集成可能因复杂操作（如 rebase）导致冲突处理复杂。
- **假设**：
  - 用户熟悉 Git 基本操作。
  - 外部依赖（如身份验证、云存储）服务稳定。
